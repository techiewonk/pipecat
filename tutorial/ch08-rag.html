Chapter 8 · Part B — Modalities & knowledge

RAG & Grounding: answers from your data

⏱ 30 minLevel: intermediate

LLMs don't know your private documents and will confidently make things up. Retrieval-Augmented Generation fetches relevant text and drops it into the context so answers are grounded — and can cite sources.

RAG is smart context-building

🎯 Concept

On each question: retrieve matching chunks (from a vector store or a file), add them to the context as a message, then let the LLM answer using them. No new pipeline magic — it's Chapter 4 context, filled intelligently. Grounding metadata adds citations; Mem0 adds long-term memory across sessions.

question ─▶ retrieve relevant text ─▶ add to LLMContext ─▶ LLM answers grounded in it
                                                          └▶ (optional) cite sources

🐍 Python note — "context stuffing"

RAG is mostly "fetch relevant text, add it to the messages list before calling the LLM." The examples use Gemini grounding and Mem0 to do the fetching.

▶️ Run it

uv run python rag/rag-gemini.py          # ask about examples/assets/rag-content.txt
uv run python rag/rag-mem0.py            # teach a fact, reconnect, it recalls

🔨 Modify it

Replace the knowledge file with your own text and ask about it. Use rag-gemini-grounding-metadata.py to print citations.

⚠️ Common errors

Answers ignore your docs → retrieval returned nothing (empty/mismatched source). No citations → use the -grounding-metadata variant.

✅ Checkpoint

In one sentence, what does RAG add to a plain LLM call?

Relevant retrieved text injected into the context so the answer is grounded in your data.
