Chapter 4 · Part A — Core

Brain & Memory: the LLM and its context

⏱ 40 minLevel: intermediate

The LLM is the reasoning core, but it's stateless — it only knows what you resend each turn. Pipecat manages that memory (the context), keeps it across sessions, and compresses it when it grows.

Context is the memory

🎯 Concept

An LLMContext is the running list of messages (system, user, assistant) sent to the model every turn. The context aggregator pair records both sides automatically. Swap models freely — each provider is an LLMService in the same slot.

user_aggregator ─▶ [ LLMContext: system, user, assistant, ... ] ◀─ assistant_aggregator
                              │ resent to the LLM every turn
                              ▼  (optional) summarizer collapses old turns

Docs: Context Management, LLM Inference.

Building & kicking off context

llm = OpenAILLMService(api_key=os.environ["OPENAI_API_KEY"],
    settings=OpenAILLMService.Settings(system_instruction="You are helpful and brief."))

context = LLMContext()
user_aggregator, assistant_aggregator = LLMContextAggregatorPair(
    context, user_params=LLMUserAggregatorParams(vad_analyzer=SileroVADAnalyzer()))

context.add_message({"role": "developer", "content": "Please introduce yourself."})
await worker.queue_frames([LLMRunFrame()])   # trigger a first response

🐍 Python note — messages are dicts

Each message is a dict with role and content. Roles: system/developer (instructions), user, assistant.

Runtime model settings

from pipecat.frames.frames import LLMUpdateSettingsFrame
await llm.queue_frame(LLMUpdateSettingsFrame({"temperature": 0.2}))

Persistence & summarization

Persistence keeps the context across reconnects/sessions (the persistent-context/ examples; realtime providers keep memory in-model). Summarization compresses old turns to stay under token limits and cost (context-summarization/). Docs: Context Summarization.

▶️ Run it

uv run python persistent-context/persistent-context-openai.py   # chat, reconnect, it remembers
uv run python context-summarization/context-summarization-openai.py

🔨 Modify it

Lower the summarization token threshold so it fires after a few turns and log the produced summary. Swap OpenAILLMService for AnthropicLLMService and confirm the pipeline is unchanged.

⚠️ Common errors

Bot "forgets" instantly → aggregators missing/misordered (assistant aggregator goes after transport.output()). Cost spikes on long chats → add summarization. Update ignored → sent before init; send after on_client_connected.

✅ Checkpoint

Why must Pipecat resend context every turn?

The LLM is stateless — it has no memory of prior turns, so the whole conversation is resent each time.
