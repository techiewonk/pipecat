Chapter 7 · Part B — Modalities & knowledge

Multimodal: vision, video & avatars

⏱ 50 minLevel: intermediate

Video frames flow through the pipeline exactly like audio. That single idea unlocks three features: seeing (vision), transforming video (processing), and giving the bot a face (avatars).

Frames carry any media

🎯 Concept

A vision model is just an LLMService that accepts image frames alongside text. Video processing is frame transformation with no LLM at all. Avatars are a video service/transport that renders a talking head from the bot's speech.

camera ─▶ [transport.input] ─▶ ImageRawFrame ─▶ [vision LLM] ─▶ "you're holding a mug"
video  ─▶ [transport.input] ─▶ VideoFrame   ─▶ [processor: mirror/filter] ─▶ [output]
speech ─▶ [avatar video service] ─▶ talking-head frames ─▶ [output]

Vision

Enable a camera-capable transport and use a multimodal LLM; when the user asks about what they're showing, the current frame is attached to the context and described. Start with vision/vision-openai.py; vision-moondream.py is a small local model.

Video processing

Pure frame work — mirror, apply filters, swap tracks, feed GStreamer sources — no AI required. Start with video-processing/video-processing-mirror.py.

Avatars (talking heads)

Tavus, HeyGen, Simli, and LemonSlice render a face driven by the bot's TTS, wired either as a transport or a video service. Start with video-avatar/video-avatar-tavus-transport.py.

▶️ Run it

uv run python vision/vision-openai.py                     # enable camera, hold something up
uv run python video-processing/video-processing-mirror.py # track transform, no AI
uv run python video-avatar/video-avatar-tavus-transport.py

🔨 Modify it

Swap vision-openai.py for vision-moondream.py and compare. Combine vision with a tool from Chapter 5 (a -video function-calling example) so the bot can both see and act.

⚠️ Common errors

No image seen → camera not enabled in the browser, or video_in_enabled=False. Avatar not rendering → vendor key/room misconfigured.

✅ Checkpoint

How do vision/ and video-processing/ differ?

Vision sends frames to an LLM for understanding; video-processing transforms the track itself, usually with no LLM.
