Multi-agent A2A patterns

⏱ 2–3 hLevel: advancedCapstone prep

Everything so far was one agent. Pipecat is also a multi-agent system: one WorkerRunner coordinates many agents talking over a shared bus. A normal bot is just the one-agent case — so every app is already A2A-ready.

Agents on a bus

🎯 Concept

A worker is a unit of work on a shared message bus. The main worker owns the transport (STT/TTS) and bridges audio to the bus; specialist workers (each an LLMWorker with its own LLM + context) sit on the bus. The six patterns below are all built from this.

                    ┌──────────── shared bus ────────────┐
 [main PipelineWorker]        [LLMWorker: greeter]   [LLMWorker: support]
 STT/TTS + transport          (own LLM + context)    (own LLM + context)
 bridges audio to bus ── activate/deactivate = "who's talking now"

Docs: Agent Handoff, Job Coordination, Distributed Agents, Proxy Agents, UI Worker, The Worker Bus.

Pattern 1 — Handoff

Several LLM agents swap "who's talking" on one audio pipeline (greeter → support).

class AcmeLLMTask(LLMWorker):
    @tool                                              # a tool exposed to THIS agent's LLM
    async def transfer_to_agent(self, params, agent: str, reason: str):
        await self.activate_worker(agent,              # hand control to another agent…
            args=LLMWorkerActivationArgs(...),
            deactivate_self=True)                       # …and step aside

# in run_bot:
runner = WorkerRunner(handle_sigint=runner_args.handle_sigint)
main = PipelineWorker(pipeline, bus=runner.bus)        # main bridges transport <-> bus
await runner.add_workers(build_greeter(), build_support(), main)   # many agents, one runner
await runner.run()

🐍 Python note — handoff is activation, not a call

Agents don't call each other like functions. The greeter activates support and deactivates itself, flipping which agent owns the shared audio.

Pattern 2 — Parallel fan-out (job coordination)

One agent dispatches a job to several peers at once and synthesizes the results.

async def debate(params, topic: str):
    async with params.pipeline_worker.job_group(       # dispatch to several peers at once
        DebateWorker("advocate"), DebateWorker("critic"), DebateWorker("analyst"),
    ) as group:
        results = await group.run(topic)               # wait for all three
    # main agent then synthesizes `results` into one spoken answer

🐍 Python note — async with … as group

An async context manager sets up the job group and guarantees cleanup; await group.run(...) gathers every peer's result before continuing.

Patterns 3–6 — sidecar, distributed, proxy, UI

  • Sidecar: the main pipeline delegates to a long-lived peer via job(...) — a codebase agent (code-assistant/) or a hardware controller (sensor-controller/).
  • Distributed: the same handoff across processes/machines over a network bus — redis-handoff/ and pgmq-handoff/. Only bus= changes.
  • Proxy: two WebSocket proxies bridge a local transport to a remote LLM worker, no shared bus (remote-proxy-assistant/).
  • UI worker: an agent bridges the bus to a web client (snapshot, deixis "explain this", form-fill, async job progress) — the ui-worker/ examples.

▶️ Run it

cd examples/multi-worker && cp env.example .env
uv run python local-handoff/local-handoff-two-agents.py    # ask something only "support" handles
uv run python parallel-debate/parallel-debate.py           # give a topic, hear 3 views synthesized

🔨 Modify it

Add a third agent ("billing") to the handoff with a transfer_to_agent path. Add a fourth DebateWorker("historian"). Point the handoff at a RedisBus to split agents across processes.

⚠️ Common errors

Handoff silent → main worker isn't bridging to runner.bus, or no agent is active on connect. Job group hangs → a peer never returns. Redis/PGMQ fails → the bus service isn't running or its URL is unset.

✅ Checkpoint

1. What makes an app multi-agent?

More than one worker on the shared bus, coordinated by one WorkerRunner.

2. How does control move in handoff?

By activating another worker and deactivating the current one — not a function call.

3. What does job_group add?

Parallel dispatch to multiple peers and collection of all results before answering.
