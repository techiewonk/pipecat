This is the chapter that separates a demo from a shippable product. Every knob that touches raw audio — voice detection, resampling, noise removal, background beds, muting, DTMF, recording — plus the general-purpose frame-processing toolbox lives here, each explained once.

The audio signal chain

🎯 Where each piece sits

Incoming audio passes through an optional noise filter and resampler before VAD and STT. Outgoing audio can be blended with a mixer (background bed) before playback. Muting gates whether user audio is processed at all. These are configured on TransportParams and on the user aggregator — not by rewriting the pipeline.

IN :  mic ─▶ [audio_in_filter: noise cancel] ─▶ [resampler] ─▶ [VAD] ─▶ STT ─▶ ...
                         (muting can drop user audio here, before it's processed)
OUT:  ... TTS ─▶ [audio_out_mixer: background bed] ─▶ speaker
REC:  [AudioBufferProcessor] taps the stream to disk

2.1 Voice Activity Detection (VAD)

VAD answers "is this speech or silence?" — the fastest turn signal (Chapter 1 uses it). Pipecat ships several engines plus tunable parameters and a controller.

from pipecat.audio.vad.silero import SileroVADAnalyzer
from pipecat.audio.vad.vad_analyzer import VADParams

vad = SileroVADAnalyzer(params=VADParams(
    confidence=0.7,      # how sure before calling it "speech"
    start_secs=0.2,      # speech must persist this long to start a turn
    stop_secs=0.8,       # silence this long ends the turn
    min_volume=0.6,
))
EngineImportWhen to use
SileroVADAnalyzerpipecat.audio.vad.sileroDefault. Fast, local, free, good enough for most apps.
AICVADAnalyzerpipecat.audio.vad.aic_vadai-coustics VAD, pairs with their noise filter.
AICQuailVADAnalyzerpipecat.audio.vad.aic_quail_vadai-coustics "Quail" model; see voice-aicoustics-vad-only.py.
KrispVivaVadAnalyzerpipecat.audio.vad.krisp_viva_vadKrisp VAD (paid); bundles well with Krisp noise/turn.

Helpers: VADParams (tuning), VADController (drives state transitions), VADProcessor (pipecat.processors.audio.vad_processor) to place VAD explicitly in a pipeline (see transcription-deepgram.py), and VADState (SPEAKING / QUIET).

2.2 Resampling (the "sampler")

Services and transports run at different sample rates (8 kHz phone audio vs. 16/24 kHz models). A resampler converts between them so nothing sounds chipmunked or clips. Usually automatic, but you can choose the engine for quality vs. speed.

from pipecat.audio.resamplers.soxr_resampler import SOXRAudioResampler
resampler = SOXRAudioResampler()          # high quality, batch
# streaming variant for realtime: SOXRStreamAudioResampler
# lightweight alternative:         ResampyResampler
ResamplerImportNotes
SOXRAudioResamplerpipecat.audio.resamplers.soxr_resamplerHigh-quality SoX resampling; good default.
SOXRStreamAudioResamplerpipecat.audio.resamplers.soxr_stream_resamplerStreaming SoX — for continuous realtime audio.
ResampyResamplerpipecat.audio.resamplers.resampy_resamplerPure-Python fallback; fewer native deps.

2.3 Noise cancellation filters

A noise filter cleans the incoming mic stream (removes background hum, keyboard, room noise) before VAD/STT — a big quality win for real calls. Attach one via audio_in_filter on the transport params.

from pipecat.audio.filters.krisp_viva_filter import KrispVivaFilter
# in transport_params:
"webrtc": lambda: TransportParams(
    audio_in_enabled=True,
    audio_out_enabled=True,
    audio_in_filter=KrispVivaFilter(),     # clean the mic before anything else
)

⚠️ Licensing — read before choosing

Three of the four need a paid SDK/key; only RNNoise is open. Pick accordingly:

FilterImportLicense / key

All subclass BaseAudioFilter, so writing your own is possible.

2.4 Background audio (mixers)

A mixer blends a sound file under the bot's speech — hold music, ambience, a "we're thinking" bed. Attach via audio_out_mixer, then control it live with frames.

from pipecat.audio.mixers.soundfile_mixer import SoundfileMixer
from pipecat.frames.frames import MixerEnableFrame, MixerUpdateSettingsFrame

"webrtc": lambda: TransportParams(
    audio_out_enabled=True,
    audio_out_mixer=SoundfileMixer(sound_files={"office": "assets/office-ambience.mp3"},
                                   default_sound="office", volume=0.3),
)
# later, at runtime:
await worker.queue_frame(MixerUpdateSettingsFrame({"volume": 0.5}))   # duck/boost
await worker.queue_frame(MixerEnableFrame(False))                     # turn bed off

Reference example: audio/audio-bot-background-sound.py.

2.5 Muting (mic-off) — server-side strategies

🎯 What "mute" means here

Rather than a client button, Pipecat mutes on the server: it drops user audio during moments where listening would cause bugs — while the greeting plays, or while a function call is running. You declare strategies and Pipecat applies them.

from pipecat.turns.user_mute import (
    MuteUntilFirstBotCompleteUserMuteStrategy,
    FunctionCallUserMuteStrategy,
)

user_params=LLMUserAggregatorParams(
    user_mute_strategies=[
        MuteUntilFirstBotCompleteUserMuteStrategy(),   # ignore mic until the intro finishes
        FunctionCallUserMuteStrategy(),                # ignore mic while a tool runs
    ],
    vad_analyzer=SileroVADAnalyzer(),
)

@user_aggregator.event_handler("on_user_mute_started")
async def _(aggregator): logger.info("mic muted")
@user_aggregator.event_handler("on_user_mute_stopped")
async def _(aggregator): logger.info("mic live")

🐍 Python note — declarative, not imperative

You don't write "if bot_speaking: drop_audio()". You add strategy objects to a list and subscribe to on_user_mute_started/stopped events for UI feedback. Reference: turn-management-user-mute-strategy.py.

2.6 DTMF & volume

On phone calls, DTMF is the keypad tones ("press 1 for sales"). Pipecat represents presses as KeypadEntry (pipecat.audio.dtmf) and can drive menus — see features/features-dtmf-menu.py. Output loudness is handled by pipecat.audio.volume.

2.7 Recording the conversation

Insert an AudioBufferProcessor (pipecat.processors.audio.audio_buffer_processor) to tap the audio stream and save it to disk without altering playback. Reference: audio/audio-recording.py.

2.8 The frame-processing toolbox

Beyond audio, Pipecat ships general-purpose processors you'll reuse constantly. A custom processor is just a class with one method:

from pipecat.processors.frame_processor import FrameProcessor

class TranscriptionLogger(FrameProcessor):
    async def process_frame(self, frame, direction):
        await super().process_frame(frame, direction)   # 1. always call super first
        if isinstance(frame, TranscriptionFrame):        # 2. react only to what you care about
            logger.info(f"User said: {frame.text}")
        await self.push_frame(frame, direction)          # 3. always forward the frame

🐍 Python note — the two mandatory calls

Every process_frame override must call super().process_frame(...) first and push_frame(...) to forward. Forgetting push_frame "swallows" frames and stalls the pipeline.

Built-in processors and filters you can drop in instead of writing your own:

🔨 Modify it

(1) Add audio_in_filter=RNNoiseFilter() to getting-started/06 and test in a noisy room. (2) Swap the mixer's sound file for your own MP3 and duck it to 0.15 while the bot speaks. (3) Add a FrameLogger after stt to watch transcripts, then a StatelessTextTransformer that upper-cases replies.

⚠️ Common errors

Pipeline stalls after adding a custom processor → missing push_frame. Noise filter import fails → that vendor's SDK/key isn't installed (use RNNoiseFilter to test the wiring first). Chipmunk/robot audio → sample-rate mismatch; let the resampler run or set the transport rate to match the service.

✅ Checkpoint

1. Which transport param cleans the incoming mic, and which adds a background bed?

audio_in_filter (noise filter) and audio_out_mixer (background mixer).

2. Which noise filter has no licensing cost?

RNNoiseFilter — open/free. Krisp, Koala, and ai-coustics need keys/licenses.

3. How is server-side muting expressed?

As a list of user_mute_strategies on LLMUserAggregatorParams, with on_user_mute_started/stopped events.
