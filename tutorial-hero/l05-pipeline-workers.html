Lesson 5 · Part I — Principles

Pipeline, workers & runner

⏱ 45 minLevel: intermediate

Three objects turn a list of processors into a running agent: the Pipeline links them, the PipelineWorker runs them, and the WorkerRunner supervises. Understand these and you understand how everything boots — including multi-agent.

From list to running agent

A Pipeline builds a PipelineSource and PipelineSink around your list, then calls _link_processors() which chains them with prev.link(curr). That's the whole "magic" of assembly — a linked list of FrameProcessors.

Lifecycle is just frames

Starting and stopping are ordinary frames on the system lane: a StartFrame flows down to initialize every service, an EndFrame shuts down cleanly, a CancelFrame aborts. You rarely send these yourself — the worker and runner do.

The minimal agent, by hand

from pipecat.pipeline.pipeline import Pipeline
from pipecat.pipeline.worker import PipelineWorker, PipelineParams
from pipecat.workers.runner import WorkerRunner

async def run_bot(transport, runner_args):
    stt, llm, tts = build_services()                       # from later lessons
    user_agg, assistant_agg = LLMContextAggregatorPair(LLMContext(),
        user_params=LLMUserAggregatorParams(vad_analyzer=SileroVADAnalyzer())).pair()

    pipeline = Pipeline([                                   # ORDER = data flow
        transport.input(), stt, user_agg, llm, tts, transport.output(), assistant_agg,
    ])
    worker = PipelineWorker(pipeline, params=PipelineParams(
        enable_metrics=True, enable_usage_metrics=True))    # config knobs

    @transport.event_handler("on_client_connected")
    async def _(transport, client):
        await worker.queue_frames([LLMRunFrame()])          # make the bot speak first

    runner = WorkerRunner(handle_sigint=runner_args.handle_sigint)
    await runner.add_workers(worker)                        # one worker now… many later
    await runner.run()

🐍 Why WorkerRunner and not just "run the pipeline"?

The runner owns the bus and can supervise many workers. Today you pass one; in Part V you pass several and they coordinate — the single-agent case is just add_workers(one). This is why Pipecat is "multi-agent ready" by default.

Branching: parallel pipelines

Need two paths from the same frames (e.g. English and Spanish TTS)? A ParallelPipeline runs branches that each receive all upstream frames; SyncParallelPipeline waits for branches to align.

from pipecat.pipeline.parallel_pipeline import ParallelPipeline
pipeline = Pipeline([
    transport.input(), stt, user_agg, llm,
    ParallelPipeline(
        [FunctionFilter(is_english), english_tts],
        [FunctionFilter(is_spanish), spanish_tts],
    ),
    transport.output(), assistant_agg,
])

✅ Checkpoint

1. What does Pipeline actually do to your list?

Wraps it in a Source/Sink and links each processor to the next with prev.link(curr) — a linked chain.

2. What's the difference between a PipelineWorker and the WorkerRunner?

The worker runs one pipeline (one agent); the runner owns the bus and supervises one or many workers.
