Lesson 15 · Part III — Realtime & multimodal

Realtime speech-to-speech

⏱ 50 minLevel: intermediateCapstone engine

Realtime models collapse STT + LLM + TTS into a single service: audio in, audio out. Lower latency, server-driven turns — and the engine our capstone standardizes on.

One service instead of three

A cascaded agent is STT → LLM → TTS (three swappable parts). A realtime service (Gemini Live, OpenAI Realtime, AWS Nova Sonic, Grok, Inworld, Ultravox) is one LLMService that consumes InputAudioRawFrame and emits TTSAudioRawFrame. Trade-off: fewer parts to swap, but much lower latency and the model manages turns itself.

Gemini Live with tools + search

from pipecat.adapters.schemas.function_schema import FunctionSchema
from pipecat.adapters.schemas.tools_schema import AdapterType, ToolsSchema
from pipecat.services.google.gemini_live.llm import GeminiLiveLLMService

weather = FunctionSchema(
    name="get_current_weather", description="Get the current weather",
    properties={"location": {"type": "string", "description": "City, State"},
                "format": {"type": "string", "enum": ["celsius", "fahrenheit"]}},
    required=["location", "format"], handler=fetch_weather)

tools = ToolsSchema(
    standard_tools=[weather],
    custom_tools={AdapterType.GEMINI: [{"google_search": {}}]})   # provider-native tool

llm = GeminiLiveLLMService(
    api_key=os.environ["GOOGLE_API_KEY"],
    settings=GeminiLiveLLMService.Settings(
        system_instruction=SYSTEM, voice="Aoede"),           # Puck, Charon, Kore, Fenrir, Aoede
    tools=tools)

pipeline = Pipeline([transport.input(), user_agg, llm, assistant_agg, transport.output()])

🐍 FunctionSchema vs docstring tools

In Lesson 12 the docstring was the schema. Realtime providers want an explicit FunctionSchema (name, properties, required, handler); provider-native tools go under custom_tools.

⚠️ Realtime quirks

Gemini Live drives turns server-side and emits no VAD/turn frames — don't build custom turn logic on those. On GeminiVertexLiveLLMService, google_search can't combine with other tools.

🔬 Source anchors

services/google/gemini_live/llm.py — GeminiLiveLLMService (marks is_realtime_service=True; consumes InputAudioRawFrame, emits TTSAudioRawFrame). Also services/openai/realtime/*, services/aws/nova_sonic/*. Adapter: adapters/services/gemini_live_adapter.

🧩 Atlas step 4

Swap Atlas's STT+LLM+TTS cascade for a single GeminiLiveLLMService. Same tools, one service. This is the engine the capstone scales into many agents.

✅ Checkpoint

1. What three services does one realtime model replace?

STT, LLM, and TTS.

2. Where do provider-native tools like google_search go?

In ToolsSchema(custom_tools={AdapterType.GEMINI: [...]}).

3. Should you add smart-turn on top of Gemini Live?

No — realtime models manage turns server-side and emit no turn frames.
