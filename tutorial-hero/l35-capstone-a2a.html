The complete bot.py — with personas, all in one

One long, runnable file. It contains the full system-prompt personas for every agent and wires in every capability from the course. Fill in your keys, a hold-music file, and a policy doc set; the shape is production-real.

"""Atlas — a Gemini Live agent-to-agent voice system (local + distributed).
Assembles the whole 0-to-Hero course into one runnable file.
"""
import os                                                     # read secrets (API keys) from the environment
from dotenv import load_dotenv                                # load those secrets from a local .env file

from pipecat.pipeline.pipeline import Pipeline                # an ordered list of processors = the agent's data flow
from pipecat.pipeline.worker import PipelineWorker, PipelineParams   # runs a pipeline as one agent + its config knobs
from pipecat.processors.frame_processor import FrameProcessor, FrameDirection  # base class for our custom Guardrail
from pipecat.processors.filters.function_filter import FunctionFilter          # keep/drop frames by a predicate
from pipecat.processors.audio.audio_buffer_processor import AudioBufferProcessor  # tap audio to disk (recording)
from pipecat.processors.aggregators.llm_context import LLMContext              # the running conversation (memory)
from pipecat.processors.aggregators.dtmf_aggregator import DTMFAggregator      # phone keypad presses -> text
from pipecat.processors.aggregators.llm_response_universal import (            # capture user/bot turns into context
    LLMContextAggregatorPair, LLMUserAggregatorParams)                         #   and the place VAD/turns/muting attach
from pipecat.frames.frames import TranscriptionFrame, LLMRunFrame              # frame types we react to / emit
from pipecat.audio.vad.silero import SileroVADAnalyzer                         # voice-activity detection (for barge-in)
from pipecat.audio.filters.rnnoise_filter import RNNoiseFilter                 # clean the caller's mic (free filter)
from pipecat.audio.mixers.soundfile_mixer import SoundfileMixer                # blend a hold-music bed under speech
from pipecat.turns.user_mute import (FunctionCallUserMuteStrategy,             # ignore the mic while a tool runs
                                     MuteUntilFirstBotCompleteUserMuteStrategy) # ignore the mic until the intro ends
from pipecat.observers.user_bot_latency_observer import UserBotLatencyObserver # measure response latency (read-only)
from pipecat.services.google.gemini_live.llm import GeminiLiveLLMService       # the speech-to-speech brain (STT+LLM+TTS)
from pipecat.services.mcp_service import MCPClient                             # attach tools hosted by an MCP server
from pipecat.workers.llm.llm_context_worker import LLMContextWorker            # an agent = its own LLM + context, on the bus
from pipecat.workers.llm.tool_decorator import tool                           # expose a method to the LLM as a tool
from pipecat.workers.llm import LLMWorkerActivationArgs                       # data handed to an agent when it is activated
from pipecat.workers.runner import WorkerRunner                               # owns the bus and supervises every worker
from pipecat.runner.types import RunnerArguments                             # what the runner / Pipecat Cloud passes to bot()
from pipecat.runner.utils import create_transport                            # builds the right transport at launch
from pipecat.transports.base_transport import TransportParams                # audio / video / filter / mixer config
from mcp import StdioServerParameters                                        # how to launch the MCP tool server
# from pipecat.bus.network.redis import RedisBus            # uncomment for DISTRIBUTED mode (agents across machines)

load_dotenv(override=True)                                    # pull GOOGLE_API_KEY etc. into os.environ

# ─────────────────────────────  PERSONAS (system prompts)  ─────────────────────────────
# A persona is the agent's system prompt — the single biggest lever on how it behaves.
# TRIAGE — the front-desk router (greets, then hands off)
TRIAGE_PERSONA = """
You are Atlas, the warm front-desk voice agent for Acme Utilities.
- Greet the caller in ONE friendly sentence.
- Decide if they need BILLING (payments, refunds, statements) or SUPPORT
  (outages, technical issues, appointments). Ask at most ONE clarifying question.
- The instant the department is clear, call route(department, reason). Do NOT try to
  resolve it yourself.
- If the caller wants multiple viewpoints or a judgment call, call consult(question).
- Keep every spoken reply under two sentences. Speak numbers naturally, no emojis.
"""
# BILLING — the billing specialist (grounds answers in policy via RAG)
BILLING_PERSONA = """
You are the Billing specialist for Acme Utilities. You have tools and policy documents.
- Verify the account before any refund. Explain charges in plain language.
- For refunds over $100, confirm the reason out loud and record it.
- Ground every factual claim in the provided policy context (RAG). If unsure, say you
  will follow up rather than guess. Be concise and warm.
"""
# SUPPORT — the support specialist (diagnoses outages / technical issues)
SUPPORT_PERSONA = """
You are the Support specialist for Acme Utilities.
- Diagnose outages and technical issues; offer the smallest next step first.
- If an on-site visit is needed, collect the address and a time window.
- Never promise a timeline you cannot confirm. Stay calm and reassuring.
"""

def redact_pii(text: str) -> str:                             # scrub sensitive data out of transcripts
    return text                                               #   (stub — plug in your real redaction)

def save_wav(audio, rate, ch):                                # write one recorded audio chunk to disk
    pass                                                      #   (stub — see Lesson 22)

def gemini(system: str) -> GeminiLiveLLMService:              # helper: build a configured Gemini Live "brain"
    return GeminiLiveLLMService(
        api_key=os.environ["GOOGLE_API_KEY"],                 # your Google key (required for every agent)
        settings=GeminiLiveLLMService.Settings(
            system_instruction=system, voice="Aoede"))        # the persona to follow + the voice to speak in

# ─────────────────────────────  MIC ON / OFF (L10)  ─────────────────────────────
async def set_mic(agent, on: bool):                           # server-side mic control (the client also has a mute button)
    await agent.llm.set_audio_input_paused(not on)            # on=False -> MIC OFF, on=True -> MIC ON
    # (cascaded agents instead push an STTMuteFrame to mute the STT input)

# ─────────────────────────────  CUSTOM PROCESSOR (L4)  ─────────────────────────────
class Guardrail(FrameProcessor):                              # a node you drop into the pipeline to inspect frames
    """Inspect every frame — here, redact PII from transcripts before they travel."""
    async def process_frame(self, frame, direction: FrameDirection):
        await super().process_frame(frame, direction)         # REQUIRED: let the base class run first
        if isinstance(frame, TranscriptionFrame):             # act only on transcribed-speech frames
            frame.text = redact_pii(frame.text)               # scrub PII before it reaches the LLM or logs
        await self.push_frame(frame, direction)               # REQUIRED: forward the frame downstream

# ─────────────────────────────  AGENTS (workers on the bus)  ─────────────────────────────
class Specialist(LLMContextWorker):                           # a specialist agent = its own Gemini brain + memory
    def __init__(self, name: str, persona: str):
        super().__init__(name=name, llm=gemini(persona), context=LLMContext())  # name it; give it a persona + context

class Triage(LLMContextWorker):                               # the front-desk agent that routes callers
    def __init__(self):
        super().__init__(name="triage", llm=gemini(TRIAGE_PERSONA), context=LLMContext())  # its own brain + memory

    @tool                                                     # exposes this method to the LLM as a callable tool
    async def route(self, params, department: str, reason: str):
        """Transfer the caller to 'billing' or 'support' (L26 handoff)."""
        await self.activate_worker(department, deactivate_self=True,   # hand control to that agent; step aside
            args=LLMWorkerActivationArgs(
                messages=[{"role": "developer", "content": f"Caller context: {reason}"}],  # pass context along
                run_llm=True))                                # make the newly-active agent respond right away

    @tool                                                     # a second tool: parallel "consult the committee"
    async def consult(self, params, question: str):
        """Ask billing AND support in parallel, then summarize (L27 fan-out)."""
        async with params.pipeline_worker.job_group(          # dispatch one job to several peers at once
                Specialist("billing_c", BILLING_PERSONA),     # a throwaway billing worker for this job
                Specialist("support_c", SUPPORT_PERSONA)) as group:   # and a support worker
            answers = await group.run(question)               # wait for all peers to answer
        await params.result_callback({"answers": answers})    # return the combined result to the LLM

# ─────────────────────────────  MAIN WORKER (owns the media)  ─────────────────────────────
transport_params = {"webrtc": lambda: TransportParams(        # "webrtc" = the REACT web client (SmallWebRTC + RTVI)
    audio_in_enabled=True, audio_out_enabled=True,            # enable the mic in and the speaker out
    audio_in_filter=RNNoiseFilter(),                          # L7: clean the caller's mic before anything else
    audio_out_mixer=SoundfileMixer(sound_files={"hold": "assets/hold.mp3"},   # L14: a hold-music bed…
                                   default_sound="hold", volume=0.15),        #      …played quietly under speech
)}
# TELEPHONY (L30): a phone call over EXOTEL hits the runner's /ws route; create_transport()
#   auto-detects Exotel and wires ExotelFrameSerializer — no branching in bot code.

async def run_bot(transport, runner_args):                    # build & run the whole system for one session
    context = LLMContext()                                    # the triage/main conversation memory
    user_agg, assistant_agg = LLMContextAggregatorPair(context,   # capture user & bot turns into that context
        user_params=LLMUserAggregatorParams(
            vad_analyzer=SileroVADAnalyzer(),                 # L7 VAD -> BARGE-IN (caller can talk over the bot)
            user_mute_strategies=[                            # L10 muting: ignore the mic when it would cause bugs…
                MuteUntilFirstBotCompleteUserMuteStrategy(),  #      …until the greeting finishes
                FunctionCallUserMuteStrategy()],              #      …and while a tool is running
            user_idle_timeout=20.0)).pair()                   # L20: nudge, then end, after 20s of silence

    guardrail = Guardrail()                                   # L4 custom processor (PII redaction)
    speech_only = FunctionFilter(lambda f: True)              # L4 frame filter (drop unwanted frame types)
    dtmf_agg = DTMFAggregator()                               # L14 turn phone keypad presses into text
    recorder = AudioBufferProcessor()                         # L22 tap the audio stream to disk for QA

    io = Pipeline([transport.input(),                         # 1. mic / network audio comes in
                   guardrail, dtmf_agg, user_agg,             # 2. guardrail -> keypad -> remember the user's turn
                   gemini(TRIAGE_PERSONA), speech_only,       # 3. the triage brain replies -> frame filter
                   assistant_agg, transport.output(),         # 4. remember the bot's turn -> play audio out
                   recorder])                                 # 5. record the whole conversation
    # cascaded specialists can also add BackchannelProcessor() (L31) + MarkdownTextFilter (L13)

    runner = WorkerRunner(handle_sigint=runner_args.handle_sigint)   # LOCAL: owns an in-memory bus (default)
    # runner = WorkerRunner(bus=RedisBus(url=os.environ["REDIS_URL"]))  # DISTRIBUTED: one line changes (L28)

    main = PipelineWorker(io, bus=runner.bus,                 # the main agent: owns the transport, bridges to the bus
        params=PipelineParams(
            enable_metrics=True, enable_usage_metrics=True,   # L23 collect TTFB + token/usage metrics
            enable_tracing=True,                              # L23 export spans to OpenTelemetry / Sentry / Langfuse
            enable_heartbeats=True,                           # L23 emit health heartbeats
            allow_interruptions=True,                         # L20 barge-in: stop speaking when the user talks
            audio_in_sample_rate=8000,                        # L7 phone audio is 8 kHz…
            audio_out_sample_rate=24000),                     #      …model audio is 24 kHz; the resampler bridges them
        observers=[UserBotLatencyObserver()])                 # L23 watch latency read-only

    @transport.event_handler("on_client_connected")           # EVENT (Appendix G): a caller / web client joined
    async def _(t, client):
        await main.queue_frames([LLMRunFrame()])              # make the bot greet first
    @recorder.event_handler("on_audio_data")                  # EVENT: the recorder produced an audio buffer
    async def _(proc, audio, sample_rate, num_channels):
        save_wav(audio, sample_rate, num_channels)            # persist it to disk (L22)

    billing = Specialist("billing", BILLING_PERSONA)          # build the billing specialist agent (RAG persona)
    await MCPClient(StdioServerParameters(command="memory-server")) \
        .register_tools(billing.llm)                          # L12: give billing an MCP memory tool

    await runner.add_workers(Triage(), billing,               # register triage + billing…
                             Specialist("support", SUPPORT_PERSONA), main)   # …+ support + the main worker
    await runner.run()                                        # start everything; block until shutdown

async def bot(runner_args: RunnerArguments):                  # the entry point the runner / Pipecat Cloud calls (L33)
    transport = await create_transport(runner_args, transport_params)   # pick WebRTC (React) or Exotel (phone)
    await run_bot(transport, runner_args)                     # run the system for this session

if __name__ == "__main__":                                    # when you run `python bot.py` directly…
    from pipecat.runner.run import main                       # …import the dev server
    main()

🐍 The whole point, in one line

Local vs. distributed is only the bus= argument. Agents, personas, tools, handoff, and fan-out are byte-for-byte identical — develop locally, scale out without a rewrite.

Two clients, one bot: React web + Exotel phone

You'll use both a React web app and an Exotel phone line — and the same bot(runner_args) serves both. create_transport() builds the right transport from how the caller arrived, so there's no branching in your bot.

React web client

import { RTVIClient } from "@pipecat-ai/client-js";
import { RTVIClientProvider, RTVIClientAudio, useRTVIClient } from "@pipecat-ai/client-react";
import { SmallWebRTCTransport } from "@pipecat-ai/small-webrtc-transport";

const client = new RTVIClient({
  transport: new SmallWebRTCTransport(),
  params: { baseUrl: "http://localhost:7860", endpoints: { connect: "/api/offer" } },
  enableMic: true, enableCam: false,          // mic on/off maps to L10
});

function App() {
  return (
    <RTVIClientProvider client={client}>
      <RTVIClientAudio />                      {/* plays the bot's audio */}
      <MicButton />                            {/* toggles the mic — barge-in still works */}
    </RTVIClientProvider>
  );
}

function MicButton() {
  const client = useRTVIClient();
  return <button onClick={() => client.enableMic(!client.isMicEnabled)}>Mute</button>;
}

The client speaks RTVI (Lesson 29): it receives the bot's audio, transcripts, and metrics events, and its mute button is the client side of "mic on/off".

Because both clients hit the one dev server and the one bot(), your agents, personas, tools, and A2A logic are identical whether the user is on the web or the phone. Only the transport differs — and the runner picks it.

Where Flows fits — and why it wasn't in the base build

🧠 Why the base build used personas, not Flows

Triage, handoff, and consult are free-form conversations — the LLM decides what to say next — so a persona prompt is enough and simpler. Flows (Lesson 19) earns its keep when a task has strict, ordered, gated steps: verify identity before anything else, collect every field of a form, follow a compliance script. The billing refund is exactly that — you must verify the account before a refund is even possible — so we wire a Flow onto the billing agent.

from pipecat.flows import FlowManager, NodeConfig   # structured, step-by-step conversations (L19)

def verify_node() -> NodeConfig:                              # STEP 1 — must happen before any refund
    return NodeConfig(
        name="verify",
        task_messages=[{"role": "system", "content": "Ask the caller for their account number."}],
        functions=[check_account])                            # only THIS tool is allowed in this node

async def check_account(flow_manager: FlowManager, account: str):   # returns (what to say, NEXT node)
    if await lookup_account(account):                         # your real verification lookup
        return "Thanks, you're verified.", refund_node()      # advance to the refund step
    return "I couldn't find that account, let's try again.", verify_node()   # stay and retry

def refund_node() -> NodeConfig:                              # STEP 2 — only reachable once verified
    return NodeConfig(name="refund",
        task_messages=[{"role": "system", "content": "Now process the refund."}],
        functions=[issue_refund])                             # the refund tool is gated behind verification

# wire the flow onto the billing agent (inside run_bot, right after you build `billing`):
flow = FlowManager(llm=billing.llm, context_aggregator=billing.user_aggregator, worker=billing)
await flow.initialize(verify_node())                          # start the caller at STEP 1

Gemini realtime gotchas

⚠️ Read before shipping

Gemini Live is speech-to-speech, so the main worker owns the transport and bridges audio; each child is a Gemini Live LLM on the bus. Gemini drives turn completion server-side and emits no turn frames — VAD here is for barge-in, not end-of-turn. And on GeminiVertexLiveLLMService, google_search can't combine with other tools (see L15).

✅ Checkpoint

1. What single change moves this system from local to distributed?

The bus= passed to the WorkerRunner — AsyncQueueBus vs RedisBus/PgmqBus. Agent code (and personas) unchanged.

2. In a realtime agent, what is VAD used for?

Barge-in — letting the caller talk over the bot. Turn completion is handled server-side by Gemini.

3. Where does the resampler ("sampler") appear?

Via PipelineParams sample rates — the streaming resampler aligns 8 kHz phone audio with 24 kHz model audio.
