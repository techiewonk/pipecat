Lesson 10 · Part II — The voice loop

Turn-taking & muting

⏱ 50 minLevel: intermediateGets it right

Knowing when the user has finished is the hardest part of natural conversation — and the thing most old tutorials get wrong. It's configured on the aggregator, not the transport.

⚠️ What changed

In this version, VAD, turn detection, and muting all live on the LLM user aggregator via LLMUserAggregatorParams — not on TransportParams. If a tutorial tells you to set turn_analyzer on the transport, it's out of date.

How a turn ends

Turn-taking is a set of strategies. Start strategies decide when a turn begins (VAD, transcription, wake-phrase, min-words); stop strategies decide when it ends. The default stop strategy is a smart-turn model gated by VAD + transcript.

Configuring it

from pipecat.processors.aggregators.llm_response_universal import (
    LLMContextAggregatorPair, LLMUserAggregatorParams)
from pipecat.turns.user_turn_strategies import UserTurnStrategies
from pipecat.turns.user_stop import TurnAnalyzerUserTurnStopStrategy
from pipecat.audio.turn.smart_turn.local_smart_turn_v3 import LocalSmartTurnAnalyzerV3
from pipecat.audio.vad.silero import SileroVADAnalyzer

user_agg, assistant_agg = LLMContextAggregatorPair(
    context,
    user_params=LLMUserAggregatorParams(
        vad_analyzer=SileroVADAnalyzer(),                       # the fast baseline
        user_turn_strategies=UserTurnStrategies(
            stop=[TurnAnalyzerUserTurnStopStrategy(
                turn_analyzer=LocalSmartTurnAnalyzerV3())],     # model refines end-of-turn
        ),
    ),
).pair()

Just a vad_analyzer gives you working turns; adding the smart-turn analyzer stops the bot from cutting you off during natural mid-sentence pauses.

Muting (mic-off), server-side

Sometimes you must ignore the user's mic — while the greeting plays, or during a tool call — so the bot doesn't interrupt itself or capture stray audio. Declare strategies:

from pipecat.turns.user_mute import (
    MuteUntilFirstBotCompleteUserMuteStrategy, FunctionCallUserMuteStrategy)

user_params=LLMUserAggregatorParams(
    user_mute_strategies=[
        MuteUntilFirstBotCompleteUserMuteStrategy(),   # ignore mic until intro finishes
        FunctionCallUserMuteStrategy(),                # ignore mic while a tool runs
    ],
    vad_analyzer=SileroVADAnalyzer(),
)

@user_agg.event_handler("on_user_mute_started")
async def _(agg): logger.info("mic muted")
@user_agg.event_handler("on_user_mute_stopped")
async def _(agg): logger.info("mic live")

Idle & interruptions

The aggregator also drives idle handling (nudge, then end, after silence) and interruptions (the user talking over the bot cancels in-flight output). Interruptions ride the system lane so they take effect instantly (Lesson 20 goes deeper).

✅ Checkpoint

1. Where are VAD/turns/muting configured?

On the user aggregator via LLMUserAggregatorParams — not the transport.

2. Name the three signals a stop strategy can combine.

VAD silence, a finalized transcript, and a smart-turn model verdict.

3. Why mute during the bot's first message?

So it doesn't capture its own audio or treat leftover noise as an interruption before the intro finishes.
