Lesson 22 · Part IV — Structure, control & capture

Transcripts & recording

⏱ 35 minLevel: intermediate

Production agents need a record: a text transcript for review/analytics and an audio recording for QA. Both tap the pipeline without disturbing the conversation.

Tap the stream

Recording audio

from pipecat.processors.audio.audio_buffer_processor import AudioBufferProcessor

recorder = AudioBufferProcessor()          # captures both user and bot audio
pipeline = Pipeline([transport.input(), stt, user_agg, llm, tts, transport.output(),
                     recorder, assistant_agg])

@recorder.event_handler("on_audio_data")   # receive buffers to persist
async def on_audio_data(proc, audio, sample_rate, num_channels):
    save_wav(audio, sample_rate, num_channels)

Saving transcripts

A transcript observer/processor collects the finalized user and assistant turns as they occur, so you can persist them or emit them to a client. Because it observes, it never risks the flow.

from pipecat.observers.transcription_log_observer import TranscriptionLogObserver
# attach to the worker so every final transcript is logged/collected
worker = PipelineWorker(pipeline, observers=[TranscriptionLogObserver()])

✅ Checkpoint

1. How do you record audio without affecting playback?

Insert an AudioBufferProcessor — it taps the stream and forwards frames unchanged, emitting buffers via on_audio_data.

2. Why capture transcripts with an observer?

Observers watch read-only, so collecting text can't stall or alter the conversation.
