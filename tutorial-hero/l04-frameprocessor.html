Lesson 4 · Part I — Principles

FrameProcessor & custom processors

⏱ 45 minLevel: beginner → intermediate

One base class powers the entire framework. Every service, transport, aggregator, and filter is a FrameProcessor. Learn its contract and you can read — and extend — anything.

The contract

A processor implements one method and obeys two rules: call super() first, and push_frame() to forward. It does not consume frames — it passes them along, optionally emitting new ones.

from pipecat.processors.frame_processor import FrameProcessor, FrameDirection
from pipecat.frames.frames import TranscriptionFrame

class TranscriptionLogger(FrameProcessor):
    async def process_frame(self, frame, direction: FrameDirection):
        await super().process_frame(frame, direction)     # 1. ALWAYS call super first
        if isinstance(frame, TranscriptionFrame):          # 2. handle only what you care about
            print(f"User said: {frame.text}")
        await self.push_frame(frame, direction)            # 3. ALWAYS forward the frame

⚠️ The #1 beginner bug

Forgetting push_frame() "swallows" frames and stalls the pipeline. Forgetting super().process_frame() breaks lifecycle handling. Every override needs both.

Direction & interruptions

FrameDirection.DOWNSTREAM is the normal flow (input → output); UPSTREAM carries things back toward the source (e.g. a processor asking the transport for a user image). Interruptions are propagated by the base class via _start_interruption() and an InterruptionFrame on the system lane — your processor usually just forwards them.

✅ Checkpoint

1. What two calls must every process_frame override make?

super().process_frame(frame, direction) first, and push_frame(frame, direction) to forward.

2. Do processors consume frames?

No — they pass them along (optionally emitting new ones), which is what lets multiple processors use the same stream.

3. You need to log frames without risk of breaking the flow — processor or something else?

Prefer an observer (Lesson 23) which watches read-only; a FrameLogger processor also works but sits in the flow.
