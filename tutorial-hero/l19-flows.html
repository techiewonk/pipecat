Flows

⏱ 50 minLevel: intermediate → advanced

For step-by-step tasks — intake, ordering, reservations, triage — one giant prompt is unreliable. Flows model the conversation as a graph of nodes, each with its own instructions and scoped tools.

Conversation as a graph

A FlowManager moves between NodeConfigs as the user progresses. Each node scopes its functions, so the bot can't wander off-task.

A node and a transition

from pipecat.flows import FlowManager, NodeConfig

def create_initial_node() -> NodeConfig:
    return NodeConfig(
        name="initial",
        role_messages=[{"role": "system", "content": "You are a friendly assistant."}],
        task_messages=[{"role": "system", "content": "Ask the user their favorite color."}],
        functions=[record_favorite_color],           # only this tool is allowed here
    )

async def record_favorite_color(flow_manager: FlowManager, color: str):
    # do something with `color`, then RETURN THE NEXT NODE to advance
    return "Thanks!", create_end_node()

# start it
flow = FlowManager(llm=llm, context_aggregator=context_agg, worker=worker)
await flow.initialize(create_initial_node())

🐍 Return (result, next_node)

A flow function returns both what to say and which node comes next. That return value is how the graph advances — the core idea of Flows. ContextStrategy (APPEND / RESET / RESET_WITH_SUMMARY) controls what carries between nodes.

✅ Checkpoint

1. What does a flow function return, and why?

A tuple of the spoken result and the next NodeConfig, so the graph advances.

2. How do you stop the bot wandering off-task?

Scope each node's tools via functions=[...] so only permitted actions are available.
