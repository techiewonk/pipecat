Interruptions, idle & switching

⏱ 40 minLevel: intermediate

Natural conversation means the user can cut in, go quiet, or need a different model mid-call. Pipecat handles all three with system-lane frames and runtime switchers.

Interruptions

Because interruptions ride the SystemFrame lane (Lesson 3), they preempt already-buffered audio. Interruptible function calls are cancelled and on_function_calls_cancelled fires. You rarely code this — it's built in — but you can tune interruption behavior.

Idle users

When the user goes quiet, a UserIdleController fires after your timeout so you can nudge, then end. The pattern keeps a retry count and escalates.

user_params = LLMUserAggregatorParams(
    vad_analyzer=SileroVADAnalyzer(),
    user_idle_timeout=8.0,      # seconds of silence before on_user_turn_idle fires
)
# handle escalation (nudge → firmer → goodbye) as in turn-management-detect-user-idle.py

Switching services at runtime

Swap a whole service — voice, model, even STT — mid-conversation with a switcher, without rebuilding the pipeline.

from pipecat.pipeline.service_switcher import ServiceSwitcher
from pipecat.pipeline.llm_switcher import LLMSwitcher

llm_switcher = LLMSwitcher([openai_llm, anthropic_llm])   # hot-swap LLMs
pipeline = Pipeline([transport.input(), stt, user_agg, llm_switcher, tts, transport.output(), assistant_agg])
# request a switch via a metadata frame; also see features-service-switcher.py

✅ Checkpoint

1. Why do interruptions take effect instantly?

They ride the high-priority SystemFrame lane, preempting buffered audio/text.

2. How do you change model/voice without rebuilding the pipeline?

Use a switcher (LLMSwitcher/ServiceSwitcher) and request a switch via a metadata frame.
