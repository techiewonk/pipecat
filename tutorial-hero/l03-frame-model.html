Lesson 3 · Part I — Principles

The frame model

⏱ 35 minLevel: beginner

Frames are the atoms of Pipecat. Learn the three scheduling lanes and how to read the 125-type taxonomy, and the rest of the framework stops being mysterious.

What a frame is

A frame is a small, typed data packet. Everything that moves through a pipeline is one: a chunk of microphone audio, a transcription, an LLM token, a "user started speaking" signal, a "shut down now" command. Every frame is a dataclass in frames/frames.py and gets a unique id/name (like TranscriptionFrame#1) for debugging.

Three lanes decide scheduling

🧠 The one idea that matters

Every frame inherits from one of three bases that control how it is queued: SystemFrame (a high-priority lane), DataFrame, and ControlFrame (both in an ordered lane). System frames can jump ahead — that's how an interruption stops the bot instantly even while audio is queued.

See frames for yourself

The fastest way to build intuition is to print every frame passing a point in the pipeline. A one-method processor does it:

from pipecat.processors.frame_processor import FrameProcessor, FrameDirection

class FrameSpy(FrameProcessor):
    async def process_frame(self, frame, direction: FrameDirection):
        await super().process_frame(frame, direction)     # always call super first
        print(f"{direction.name:10} {type(frame).__name__}")
        await self.push_frame(frame, direction)           # always forward

# drop it anywhere in a pipeline, e.g. right after transport.input()
pipeline = Pipeline([transport.input(), FrameSpy(), stt, ...])

Run any voice example with FrameSpy inserted and you'll watch InputAudioRawFrame, UserStartedSpeakingFrame, TranscriptionFrame, LLMTextFrame, TTSAudioRawFrame stream by — the whole conversation as data.

✅ Checkpoint

1. Why do system frames need their own high-priority lane?

So control signals — especially interruptions — can preempt already-buffered data (audio/text) and take effect immediately.

2. Which base would a "user started speaking" event use, and which would output audio use?

The speaking event is a SystemFrame (UserStartedSpeakingFrame); output audio is a DataFrame (OutputAudioRawFrame/TTSAudioRawFrame).
