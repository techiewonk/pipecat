Lesson 24 · Part V — Multi-agent

The worker bus & bridge

⏱ 45 minLevel: advanced

Everything so far was one agent. Pipecat is also multi-agent: one WorkerRunner coordinates many workers over a shared bus. A normal bot is just the one-worker case — so every app is already A2A-ready.

Workers on a bus

The bus carries typed messages, not raw frames — frames ride the bus only when wrapped in a BusFrameMessage. System messages (interruptions, cancel) get a high-priority queue, just like system frames in a pipeline.

Bridging a pipeline to the bus

from pipecat.workers.runner import WorkerRunner
from pipecat.pipeline.worker import PipelineWorker

runner = WorkerRunner(handle_sigint=runner_args.handle_sigint)   # owns the bus
main = PipelineWorker(pipeline, bus=runner.bus)                  # tee frames to the bus
await runner.add_workers(main, GreeterWorker(), SupportWorker())  # many workers, one runner
await runner.run()

A BusBridgeProcessor sends most frames to the bus (consuming them locally) while letting lifecycle frames pass through; incoming bus frames are injected back into the pipeline. When a PipelineWorker is bridged, it tees frames both locally and to the bus via internal edge processors.

Three bus implementations

BusWhereUse
AsyncQueueBusbus/local/async_queue.pyIn-process (default) — one machine.
RedisBusbus/network/redis.pyAcross processes/machines via Redis pub/sub.
PgmqBusbus/network/pgmq.pyPostgres/Supabase message queue — ops-friendly.

Swapping between them is a one-line change on the runner (Lesson 28).

✅ Checkpoint

1. What makes an app multi-agent?

More than one worker on the shared bus, supervised by one WorkerRunner.

2. How does audio reach a specialist worker that doesn't own the mic?

The main worker bridges its frames onto the bus as BusFrameMessages; specialists subscribe.
