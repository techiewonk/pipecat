Lesson 28 · Part V — Multi-agent

Distributed & proxy

⏱ 50 minLevel: advanced

The payoff of the bus abstraction: run the exact same agents across separate processes or machines by changing one line — the bus.

Same code, network bus

The one-line change

from pipecat.bus.network.redis import RedisBus
# LOCAL (default): runner owns an in-memory AsyncQueueBus
runner = WorkerRunner(handle_sigint=runner_args.handle_sigint)
# DISTRIBUTED: point every process at the same Redis channel
runner = WorkerRunner(bus=RedisBus(url=os.environ["REDIS_URL"]))
# PgmqBus(...) is the Postgres/Supabase alternative
# Each process runs its own WorkerRunner with the SAME bus config and adds its workers.

🧠 Why this is the whole point

You develop and debug locally with the in-memory bus, then scale out to separate machines by swapping the bus — no rewrite. Cross-runner registries let workers discover each other across the network.

Proxy: bridge without a shared bus

When two agents can't share a bus (different networks, firewalls), a pair of WebSocket proxy workers forward messages between them point-to-point.

from pipecat.workers.proxy.websocket.server import WebSocketProxyServer
# a server proxy exposes local bus traffic over WebSocket; a client proxy connects remotely
# see examples/multi-worker/remote-proxy-assistant/

bus/network/redis.py — RedisBus. bus/network/pgmq.py + pgmq_backends.py — PgmqBus. workers/proxy/websocket/{server,client}.py — proxy workers. workers/runner.py — cross-runner registry exchange. Examples: multi-worker/distributed-handoff/{redis-handoff,pgmq-handoff}/, multi-worker/remote-proxy-assistant/.

✅ Checkpoint

1. What single change moves agents from local to distributed?

The bus= passed to the WorkerRunner — in-memory vs. RedisBus/PgmqBus. Agent code is unchanged.

2. When do you need proxy workers instead of a shared bus?

When agents can't share a bus (separate networks/firewalls) — proxies forward messages point-to-point over WebSocket.
