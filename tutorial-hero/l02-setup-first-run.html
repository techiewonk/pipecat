Lesson 2 · Part I — Principles

Setup & first run

⏱ 25 minLevel: beginner

Get a bot talking in five minutes, then understand exactly what happened. This is also Atlas step 0 — the first move of the capstone project.

Install

Pipecat uses uv. From the repo root:

▶️ One-time setup

uv sync --all-extras          # install Pipecat + every provider "extra"
cp env.example .env           # then edit .env and add your API keys

An extra is an optional dependency group named after a provider — e.g. pipecat-ai[deepgram,cartesia,openai,silero]. --all-extras just installs them all so nothing is missing while you learn.

Run your first bot

▶️ Say one thing

uv run python getting-started/01-say-one-thing.py
# open http://localhost:7860/client/ and click Connect — the bot says "Hello there!"

You only need a Cartesia key for this one (it's TTS-only — no microphone, no LLM). That single run exercises the whole runtime: a transport, a pipeline, a worker, and the runner.

What just happened

The anatomy of every example

Open getting-started/01-say-one-thing.py. Every Pipecat program has this shape — memorize it:

transport_params = {                       # how the user connects (picked at launch)
    "webrtc": lambda: TransportParams(audio_out_enabled=True),
    "daily":  lambda: DailyParams(audio_out_enabled=True),
}

async def run_bot(transport, runner_args):
    tts = CartesiaTTSService(api_key=os.environ["CARTESIA_API_KEY"],
        settings=CartesiaTTSService.Settings(voice="71a7ad14-...-01c121"))
    worker = PipelineWorker(Pipeline([tts, transport.output()]))   # a 2-stage pipeline

    @transport.event_handler("on_client_connected")
    async def on_client_connected(transport, client):
        await worker.queue_frames([TTSSpeakFrame("Hello there!"), EndFrame()])

    runner = WorkerRunner(handle_sigint=runner_args.handle_sigint)
    await runner.add_workers(worker)
    await runner.run()

async def bot(runner_args):                # entry point (also used by Pipecat Cloud)
    transport = await create_transport(runner_args, transport_params)
    await run_bot(transport, runner_args)

if __name__ == "__main__":
    from pipecat.runner.run import main
    main()

🐍 Python note — os.environ[...] and .env

load_dotenv() reads your .env file into the environment; os.environ["CARTESIA_API_KEY"] pulls a key back out. Secrets never live in code.

🔬 Source anchors

runner/run.py — the dev server that serves the web client and dispatches to your bot(). runner/utils.py — create_transport() picks the transport from runner_args. runner/types.py — RunnerArguments. We open these fully in Lesson 30.

Try another transport

Because the transport is chosen at launch, the same bot runs over WebRTC, Daily, or a phone with a flag:

uv run python getting-started/01-say-one-thing.py -t daily     # needs DAILY_API_KEY
uv run python getting-started/06-voice-agent.py                # a full two-way voice agent

🧩 Atlas step 0

Copy 01-say-one-thing.py to atlas.py and change the greeting to introduce your assistant by name. That's the seed we grow for the rest of the course.

🔨 Exercise

(1) Change the Cartesia voice id. (2) Queue two TTSSpeakFrames before the EndFrame and confirm they play in order. (3) Run 06-voice-agent.py and have a real conversation.

⚠️ Common errors

KeyError: 'CARTESIA_API_KEY' → not in .env (or you skipped cp env.example .env). Silent browser → allow audio and confirm http://localhost:7860/client/. Address already in use → another example is running; stop it or add --port 7861.

✅ Checkpoint

1. Why does 01-say-one-thing.py not need an LLM or a microphone key?

It only speaks a fixed line — a TTS service plus the transport output. No user input, no generation.

2. What picks the transport at launch?

create_transport(runner_args, transport_params) — it reads the runner_args type set by the -t flag / dev runner.
