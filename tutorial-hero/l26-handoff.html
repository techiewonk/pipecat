Lesson 26 · Part V — Multi-agent

Handoff

⏱ 45 minLevel: advanced

Handoff is how several agents share one conversation: they swap "who's talking" on the same audio pipeline. A greeter routes you to support; support takes over seamlessly.

Swapping who's active

🧠 Handoff is activation, not a function call

Agents don't call each other like functions. One agent activates another and deactivates itself, flipping which worker owns the shared audio. The main (transport-owning) worker keeps bridging audio the whole time.

The handoff tool

from pipecat.workers.llm.llm_context_worker import LLMContextWorker
from pipecat.workers.llm.tool_decorator import tool
from pipecat.workers.llm import LLMWorkerActivationArgs

class GreeterAgent(LLMContextWorker):
    @tool
    async def transfer_to(self, params, agent: str, reason: str):
        """Transfer the conversation to another agent."""
        await self.activate_worker(
            agent,
            args=LLMWorkerActivationArgs(messages=[{"role": "developer",
                "content": f"Context: {reason}"}], run_llm=True),
            deactivate_self=True,               # step aside
        )

# in run_bot: main owns the transport; greeter + specialists live on the bus
await runner.add_workers(GreeterAgent("greeter"), BillingAgent("billing"),
                         SupportAgent("support"), main)

On activation, an LLMWorker sends its tools and any seed messages, then responds — so the newly active agent greets with the handed-over context. on_activated/on_deactivated hooks let you react.

✅ Checkpoint

1. How does control move between agents in handoff?

By activating another worker and deactivating the current one — not a function call.

2. Who owns the microphone during a handoff?

The main (transport) worker — it keeps bridging audio while the active brain changes.
