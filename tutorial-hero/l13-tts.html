Lesson 13 · Part II — The voice loop

Text to Speech

⏱ 40 minLevel: intermediate

TTS is the bot's voice: LLM text in, audio out. Drop-in like STT, with a few powerful extras — sentence aggregation, word timestamps, and skipping speech.

Text in, audio out

Configure a voice, switch it live

from pipecat.services.cartesia.tts import CartesiaTTSService
from pipecat.frames.frames import TTSUpdateSettingsFrame

tts = CartesiaTTSService(api_key=os.environ["CARTESIA_API_KEY"],
    settings=CartesiaTTSService.Settings(voice="71a7ad14-...-01c121"))

# switch voice mid-conversation (Settings pattern from Lesson 11):
await tts.queue_frame(TTSUpdateSettingsFrame({"voice": "<another-voice-id>"}))

-http variants return audio in one response; the default streams it as generated (lower latency). WebSocket providers (Cartesia, ElevenLabs, Rime) also give word timestamps for precise interruption handling and subtitles.

Skipping speech & transforms

Sometimes text should flow through the pipeline (update context, reach processors) without being spoken — e.g. structured markers. Set skip_tts, or use an LLMTextProcessor with a pattern aggregator to skip code blocks or reshape text just-in-time.

from pipecat.frames.frames import LLMConfigureOutputFrame
await worker.queue_frame(LLMConfigureOutputFrame(skip_tts=True))    # don't speak the next output
# ... later ...
await worker.queue_frame(LLMConfigureOutputFrame(skip_tts=False))

# TTS-only text transforms (e.g. spell out phone numbers) without touching the LLM text:
tts.add_text_transformer(spell_out_numbers, "phone_number")

✅ Checkpoint

1. Streaming vs -http TTS — the difference?

Streaming emits audio as it's generated (lower latency); -http returns it in one response (simpler, slightly higher latency).

2. What does skip_tts allow?

Text to flow through the pipeline and into context without being spoken — useful for structured markers or text-only responses.
