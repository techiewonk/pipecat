Meet the worker hierarchy — from a bare coordinator to a full LLM agent — the @tool decorator that exposes methods to an agent's LLM, and how workers discover each other.

The worker hierarchy

Exposing tools with @tool

from pipecat.workers.llm.llm_context_worker import LLMContextWorker
from pipecat.workers.llm.tool_decorator import tool

class BillingAgent(LLMContextWorker):
    @tool
    async def refund(self, params, order_id: str, reason: str):
        """Issue a refund for an order."""
        result = await do_refund(order_id, reason)
        await params.result_callback(result)

# @tool methods are auto-registered with this worker's LLM on activation.

🐍 Deferred frames during tool calls

An LLMWorker tracks in-flight tool calls and defers frames queued during execution, flushing them after — so a mid-tool interruption or handoff behaves correctly.

Registry & discovery

Workers self-register with a WorkerRegistry on attach, and can signal readiness with @worker_ready. That's how a coordinator knows which agents exist and when they're available to activate or dispatch to. Across runners, registries are exchanged so agents on different machines can find each other.
