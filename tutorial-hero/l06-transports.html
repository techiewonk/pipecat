Lesson 6 · Part II — The voice loop

Transports

⏱ 35 minLevel: intermediate

The transport is how the user reaches your bot — the first and last processor in every pipeline. Swap it without touching your logic.

Input and output

A transport exposes two processors: input() (produces incoming audio/video frames) and output() (consumes outgoing ones). Everything you build sits between them.

TransportParams: the shared config

Every transport is configured with TransportParams (or a subclass). It controls audio/video enablement and rates, plus two important hooks you'll use later:

from pipecat.transports.base_transport import TransportParams

params = TransportParams(
    audio_in_enabled=True,
    audio_out_enabled=True,
    audio_out_sample_rate=24000,        # match your TTS for best quality
    video_in_enabled=False,
    audio_in_filter=None,               # noise cancellation goes here (Lesson 7)
    audio_out_mixer=None,               # background audio bed goes here (Lesson 14)
)

🧠 What is NOT here anymore

VAD, turn detection, and serializers are not on TransportParams in this version. VAD/turns live on the aggregator (Lesson 10); serializers are a per-transport param only for raw-socket transports (telephony, Lesson 30).

WebRTC is recommended for client apps (low latency, echo cancellation, resilience); WebSocket suits server-to-server and telephony. Because the choice is made at launch, one bot serves all of them:

uv run python getting-started/06-voice-agent.py            # default (SmallWebRTC)
uv run python getting-started/06-voice-agent.py -t daily   # Daily rooms

The output side does real work

The output transport isn't a dumb sink — its internal MediaSender resamples audio to the device rate, chunks it, applies the mixer, tracks bot-speaking (emitting BotStartedSpeakingFrame/BotStoppedSpeakingFrame), handles interruptions, and can fan out to multiple destinations. You'll revisit it in Lesson 14.

✅ Checkpoint

1. Where in the pipeline does a transport sit, and why does that make it swappable?

First (input()) and last (output()) — the boundary with the outside world, so the middle of the pipeline never changes when you switch transports.

2. Which two optional hooks live on TransportParams?

audio_in_filter (noise cancellation) and audio_out_mixer (background audio).
